# 盘点注意事项

简体中文 | [English](inspection.en.md)

按当前范围选用下面的方法，不必每次全盘扫描。命令参数应使用核实后的路径并正确引用，避免把用户文件名当作 shell 代码。

## 空间和性能口径

- `df -k /System/Volumes/Data` 提供数据卷的当前真实可用空间。记录原始输出、时间和单位；系统设置中的“可用”可能包含可清除空间，不能混用两种读数。
- `du -sk <确切目录>` 统计分配块。检查退出状态和 stderr；部分不可读时标为不完整，不把输出当作精确总量。
- 对云盘、iCloud、NAS 和稀疏文件，以本地分配块和文件状态判断；不要读取云端占位文件内容来“验证大小”并触发批量下载。APFS clone、快照、压缩、硬链接也会改变释放量。
- 卡顿排查可按需读取 `sysctl vm.swapusage`、`sysctl kern.memorystatus_vm_pressure_level`、`uptime` 和短时进程样本。某些命令或字段可能随系统不同而不可用。积累的 swap、瞬时 CPU、基础 SMART 和一次压力采样都不能单独证明持续性能或硬件问题。

## 容易遗漏的大项

先观察应用目录、用户与系统缓存、Application Support、容器、下载目录、明确的开发工作区和废纸篓。CacheStorage、WebStorage、更新器 payload、旧程序版本、构建产物可能由大量小文件组成，大文件搜索不能替代目录统计。

范围较大时分阶段读取元数据，避免调查本身持续增加磁盘或内存压力。优先使用 rg 查找已知项目的记录/配置；不跟随软链接扩展到其他卷，不顺带读取所有个人文件内容。

## 各类候选的证据要求

| 类别 | 需要核对 | 不能推定 |
|---|---|---|
| 卸载残留 | 应用是否确已移除、bundle ID、对应服务和路径用途 | 应用不存在就能删所有同厂商共享目录 |
| 浏览器/Electron 缓存 | Cache 与账号数据库的边界，离线资料是否需要保留，相关进程 | CacheStorage 一定不含用户需要的离线内容；“清浏览器”就代表清账号 Profile |
| 旧扩展/旧程序包 | obsolete/版本列表、current 入口、运行进程的实际二进制路径 | 版本号较旧就没人使用；此前存在的候选现在仍在 |
| 开发缓存/产物 | 锁文件、源码位置、当前构建、依赖内手工修改、离线需求 | 所有 node_modules、target、registry、pkgs 都可直接删 |
| Conda | 当前 clean dry-run、登记环境、指向缓存的软链接和自定义环境线索 | clean 安全预览允许删整个 pkgs 或 force-pkgs-dirs；登记环境检查覆盖所有自定义环境 |
| 模型缓存 | 模型本体与 token/配置分开，工具依赖和重新下载条件 | 缓存路径内全部内容都是可下载模型 |
| 游戏 | 实际名称、app ID、安装目录、存档/Steam userdata | 安装目录名就是实际游戏名；卸载可包含删存档 |
| 电子书/个人文件 | 对应副本、文件集合、实际内容校验与源文件变化 | 同名、同标题、相近大小就证明已有完整归档 |
| 废纸篓 | 当前具体内容、是否是审核过的那一批 | 可以顺手清空两个用户或管理员的整个废纸篓 |
| Time Machine/APFS | 快照类型、精确标识、回滚用途、系统原生处理方式 | 把系统更新快照与 Time Machine 快照混为一谈；重复相加快照与可清除空间 |
| 系统图标/语音/模型/索引 | 当前系统机制、原生管理入口、占用与保护状态 | 从历史经验复制一条通用 rm 命令；无法读到就可删除 |

## 工具与权限

优先使用本机工具和应用自身操作。涉及具体软件的未知行为时查当前官方文档或本机 help/man；论坛经验用于发现线索，不能代替范围验证。系统与应用清理入口会随版本变化。

没有完全磁盘访问或管理员权限时，列出已完成范围和具体受限路径；所需授权按当前环境处理。取得权限后补查，避免继续把历史访问错误写成当前未知。系统拒绝正常权限删除时，不修改 SIP 或受保护标记去凑空间。
